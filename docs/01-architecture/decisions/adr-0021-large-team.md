# ADR-0021: 大团队设计基线（150 人）——分域凭证、治理分流与性能基准

日期：2026-11-18　状态：accepted

## 设计宪法（本地优先红线，任何后续功能不得违背）

1. 检索默认走本地，中心检索必须显式指定 remote。
2. 本地操作在断网时完整可用（零网络原则）。
3. 中心不成为 ID/序列发放方（ID 恒由本地序列生成）。
4. 删除中心 = 本地无损（可逆性验收项）。

## 分域凭证（per-domain token）

- 中心 serve：`--token <admin>`（管理员钥）+ `--domain-tokens "team-frontend=tkA,team-backend=tkB"`
- 写侧：域 token 推送的提案**自动归属该域**（未标注 scope 时注入）；**跨域推送 403 拒绝**；
  管理员钥可推任意域。
- 读侧不变（调用方声明 ?team=，ADR-0019）。

## 治理分流

- `/api/inbox` 返回 `groups`（按域计数）与条目 `domain` 字段；`?domain=<id>` 切片。
- CLI `memhub inbox list --team <domainId>` 同过滤。
- 150 人 ≈ 10–20 个域，各域管理员审各自域的收件箱切片。

## 性能基准（本机 150 人年度库模拟：20 域 × 1000 条 + 150 提案）

| 操作 | 实测 | 结论 |
|---|---|---|
| 1000 条写入 | 7.2s（7ms/条，title 缓存增量维护后，原 O(n²) 为 262s） | ✅ |
| 索引构建 | 556ms | ✅ |
| 域内检索均值 | **0.19ms** | ✅ 交互级 |
| curate（150×1000 比较） | 737ms | ✅ |

已知边界：软删条目的 title 缓存行随目录 mtime 失效前可能残留（低频、有明确报错，
下次进程/目录变更自愈）；万条级以后再评估物理分区（domainId 即分区键）。
