# Compatibility Policy

> 格式与行为兼容的策略层。宿主逐个验证记录见 [COMPATIBILITY.md](../COMPATIBILITY.md)。

## 格式兼容（硬契约）

1. **frontmatter 契约面**：必需键/可选键/scope 三形态/未知键保留——由 `tests/format.test.ts` 锁定。任何改动必须：先改测试样例（样例必须来自真实 hub，不许发明语法）→ 改解析器 → 两仓同步。
2. **目录布局**：`knowledge/<type>/<ID>.md`、`pending/PRO-*.md`、`history/<type>/<ID>@v<N>.md`、`records/ledger.jsonl`——变更属于破坏性变更，需 ADR + 两仓同步 + 版本号 major/minor 升位。
3. **旧 hub 直接可读**：本仓任何版本必须能打开旧仓创建的 hub（45+ 条真实数据回归）。
4. **新 hub 被旧仓可读**：本仓 commit 产物必须能被旧仓打开（双向；一旦单向破坏即立刻停版本对齐修复）。

## 行为兼容

1. **写锁互操作**：旧仓插件持锁时，本仓入口必须同样如实报 `readOnly: true` + 租约信息（租约文件格式 🔗 继承旧仓 ADR-0009）。
2. **错误语义**：工具错误码与旧仓 memory_* 工具保持同义（模型侧提示语可以不同，错误码不能漂移）。
3. **`memory_*` 工具名冻结**：跨宿主四宿主实测过的工具名不改名。

## 验证状态三档（不许混用）

| 档 | 含义 | 标注 |
| --- | --- | --- |
| 实测 | 在真实宿主端到端跑通 | ✅ 实测 |
| 文档 | 宿主官方文档支持但未实测 | 📄 文档 |
| 待核 | 设计假设，未验证 | ⏳ 待核 |

继承自旧仓的实测数据在新仓复验前一律降档为"⏳ 待核（旧仓已实测）"。
