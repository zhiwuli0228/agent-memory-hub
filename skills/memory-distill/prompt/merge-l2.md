# L2 合并提示词：条目 → 更高层洞察（可选阶段）

> 用途：当同一主题下积累了多条 L1 条目，把它们归纳成一条更高层的认识。
> 版本：distill-v1
> **重要**：L2 只产出 pending，**绝不覆盖 L1**。被新洞察取代的 L1 通过 `supersedes` 升版本，保留原文。

## 何时启用

- 某主题下已有 ≥3 条 L1 条目，且它们指向同一类结论
- 用户在复盘/总结时明确要求「把这些整理成一条」

**不满足就不要跑 L2**——强行归纳会制造一条空泛的正确废话，反而污染检索。

## 硬要求

1. **≥2 条证据**：L2 洞察必须至少引用 2 条既有条目（`evidence: ["KNO-000001", "KNO-000004"]`）作为支撑，否则不予采纳。
2. **有增量**：L2 必须说出 L1 各自说不出的东西（共性规律、适用边界、失效条件）。如果只是把 L1 拼起来 → 不做。
3. **不覆盖**：L2 是新增条目；如要修订某条 L1，走 `supersedes: [KNO-xxxxxx]` 升版本，原文进 history。
4. **可回溯**：正文必须能指回具体 L1 条目 id。

## 输出结构

```
type: knowledge | process | playbooks
title: <共性结论>
summary: <一两句，含适用边界>
body:
  ## 结论
  ## 支撑（逐条列 L1 id + 要点）
  ## 适用边界（什么情况下这条不成立）
  ## 失效条件（什么变化会让它过期）
sourceRefs: ["note: <引文>", ...]
```

## 反例

- ❌ 把 3 条「某组件有坑」拼成「某组件有几个坑」→ 无增量，丢
- ❌ 归纳出一条「要注意配置正确性」→ 空泛正确废话，丢
- ✅ 「这三件事的共同根因是凭据解析发生在启动期，所以任何凭据格式错误都表现为服务起不来而非运行时告警」→ 有增量，保留
